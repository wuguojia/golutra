# AI 员工档案：技术栈探测员

> **角色代号**：Tech Stack Detective  
> **推荐 CLI**：Claude Code  
> **角色类型**：`assistant`  
> **出现方案**：方案一、五、七（任何需要技术栈感知的方案）

---

## 一、基础信息

| 属性 | 值 |
|------|-----|
| 角色定位 | 探测项目技术栈，生成上下文摘要，广播给所有 Worker |
| 推荐 CLI | Claude Code（文件分析能力强） |
| 替代 CLI | Gemini CLI |
| 推荐实例数 | 1（全局唯一探测者） |
| 沙盒模式 | ❌ 关闭（需要读取项目文件） |
| 无限制模式 | ✅ 开启 |

---

## 二、为什么需要这个角色？

golutra **目前不会自动检测项目技术栈**。当你邀请多个 Worker 后，它们各自独立工作，不知道项目用了什么框架、什么语言、什么构建工具。

**技术栈探测员**解决这个问题：
1. 第一个启动，扫描项目的配置文件
2. 生成一份标准化的技术栈摘要
3. 你把摘要用 **@All** 广播给所有 Worker
4. 所有 Worker 后续工作都基于这份上下文

---

## 三、页面配置步骤

### 第一步：邀请技术栈探测员

1. 在聊天界面点击 **"邀请助手"**
2. 在弹窗中配置：
   - **模型选择**：**Claude Code**（点击橙色图标那行）
   - **实例数量**：**1**
   - **无限制访问**：**✅ 开启**
   - **沙盒模式**：**❌ 关闭**
3. 点击**发送邀请**

### 第二步：给它改名（推荐）

1. 在成员列表找到新创建的 `xxx-assistant-claude-N`
2. 点击头像 → **管理成员**
3. 把**显示名称**改为 `技术栈探测员`
4. 点击保存

### 第三步：发送探测指令

**私聊**技术栈探测员（点击它的头像进入 DM），发送以下 Prompt：

```

1. package.json → 提取 dependencies、devDependencies
2. tsconfig.json → 确认 TypeScript 配置
3. vite.config.ts / vite.config.js → 确认构建工具
4. nuxt.config.ts → 确认 Nuxt
5. next.config.js → 确认 Next.js
6. tailwind.config.js / tailwind.config.ts → 确认 CSS 框架
7. .eslintrc* / eslint.config.* → 确认 Lint 配置
8. Cargo.toml → 确认 Rust
9. go.mod → 确认 Go
10. requirements.txt / pyproject.toml / setup.py → 确认 Python
11. Dockerfile / docker-compose.yml → 确认容器化
12. .github/workflows/ → 确认 CI/CD

请输出以下标准格式：

只输出上面的摘要，不要额外解释。
```

### 第四步：用 @All 广播给所有 Worker

1. 等技术栈探测员输出摘要后
2. **复制摘要内容**
3. 回到**群聊频道**
4. 输入 `@All` 然后粘贴摘要：

```
@All 本项目的技术栈信息，请所有人记住，后续工作严格遵守：

{粘贴技术栈摘要}

编码规范补充：
- Vue 组件使用 <script setup lang="ts">
- 状态管理用 Pinia（不用 Vuex）
- 样式用 Tailwind CSS
- 暗色模式必须适配
```

5. 发送 → 所有 Worker **同时收到**并记住技术栈上下文

## 四、Prompt 模板库

### 4.1 基础探测（首次使用）

```
扫描当前项目根目录的所有配置文件，输出一份标准化的技术栈摘要。
包含：语言、框架、构建工具、CSS 方案、测试框架、包管理器、关键依赖版本。
格式清晰，用 Markdown 表格。
```

### 4.2 深度探测（含项目结构）

```
除了技术栈探测外，还需要分析：
1. 项目目录结构（src/ 下的一级目录及其用途）
2. 入口文件（main.ts / App.vue / index.ts）
3. 路由结构（如有 router 配置）
4. Store 结构（如有 Pinia/Redux stores）
5. API 层结构（如有 api/ 或 services/ 目录）

输出完整的项目地图，帮助其他 Worker 理解代码组织。
```

### 4.3 增量探测（项目更新后）

```
项目依赖已更新，请重新扫描 package.json 和 lock 文件。
与上次探测结果对比，列出：
1. 新增的依赖
2. 删除的依赖
3. 版本变更的依赖
4. 对现有代码的潜在影响
```

### 4.4 多语言项目探测

```
这是一个 Monorepo 或多语言混合项目。请扫描：
1. 根目录配置（package.json, Cargo.toml 等）
2. 所有子目录的技术栈（如 src-tauri/, packages/, apps/）
3. 工作区配置（pnpm-workspace.yaml, turbo.json 等）
4. 跨项目共享的配置

分别输出每个子项目的技术栈摘要。
```

## 五、协作关系

```
技术栈探测员（第一个启动）
  │
  ├── 输出技术栈摘要
  │
  ▼
你（复制摘要，@All 广播）
  │
  ├──→ 编码助手 ×N（按正确的框架和规范写代码）
  ├──→ 测试专家（按正确的测试框架写测试）
  ├──→ 架构审查员（基于真实技术栈做架构评审）
  ├──→ 安全审查员（检查特定框架的安全问题）
  ├──→ 性能审查员（针对性分析框架性能问题）
  └──→ 文档工程师（按正确的技术栈写文档）
```

## 六、进阶用法

### 6.1 搭配需求分析师使用

如果你用方案七（需求驱动），可以让需求分析师**自动调用**技术栈探测：

```
@需求分析师 在分析需求之前，请先：
1. 让技术栈探测员扫描项目
2. 基于技术栈摘要分析实现方案
3. 分配任务时附上技术栈约束
```

### 6.2 保存为复用模板

探测到的技术栈摘要可以保存在项目的 `.golutra/` 目录或 README 中，下次打开工作区时直接复制广播，不需要重新探测。

### 6.3 定期更新

每次安装/更新依赖后（`pnpm install`），重新让探测员扫描并广播变更。

---

## 七、微调建议

| 场景 | 调整 |
|------|------|
| 纯前端项目 | 可跳过后端/数据库探测 |
| Monorepo | 需要探测每个子包 |
| 遗留项目 | 增加探测 jQuery、Webpack 3 等旧版配置 |
| Rust/Go 项目 | 侧重探测 Cargo.toml 或 go.mod |
