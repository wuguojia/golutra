# 方案七：需求驱动智能工作流（需求分析 → 审批 → 统筹安排）

> **方案代号**：Demand-Driven Workflow  
> **适用场景**：你只需描述一个简单需求，AI 自动分析拆解，你审批通过后，AI 军团自动统筹执行  
> **推荐指数**：⭐⭐⭐⭐⭐（终极效率模式）  
> **所需 CLI**：Claude Code + Gemini CLI + 系统终端  
> **AI 员工总数**：5-10 个（按需自动分配）  
> **预计效率提升**：1000%–1500%（一句话需求 → 完整交付）

---

## 一、方案概述

这是 golutra 最高级的使用模式。你不再需要逐个给 AI 员工分配任务——你只需用一句话描述需求，AI 需求分析师会自动：

1. **分析需求** → 拆解为具体任务
2. **生成执行计划** → 分配给合适的 AI 员工
3. **你审批通过** → 一键启动
4. **AI 统筹执行** → 自动编排、监控、汇总

### 核心理念

```
你（一句话需求）
  │
  ▼
🧠 需求分析师 (Claude)
  │
  ├── 分析需求 → 拆解任务清单
  ├── 评估资源 → 推荐 AI 员工组合
  ├── 生成执行计划 → 时间线 + 依赖关系
  │
  ▼
你（审批 / 修改 / 驳回）
  │
  ▼  ✅ 审批通过
🧠 需求分析师 → 统筹调度
  │
  ├── @编码助手-1: "实现 XXX 组件"
  ├── @编码助手-2: "实现 YYY 页面"
  ├── @测试专家:   "编写 XXX 和 YYY 的测试"
  ├── @Shell执行器: "pnpm test && pnpm build"
  └── @文档工程师:  "生成组件文档"
  │
  ▼
📊 执行报告 → 你确认验收
```

### 与其他方案的本质区别

| 维度 | 方案一~六 | 方案七（本方案） |
|------|----------|----------------|
| 任务分配 | 你手动 @每个员工 | AI 自动分析+分配 |
| 任务粒度 | 你自己拆解 | AI 自动拆解 |
| 员工选择 | 你决定用谁 | AI 推荐最优组合 |
| 执行编排 | 你控制先后顺序 | AI 自动编排依赖 |
| 你的角色 | 监工（细粒度管理） | 决策者（审批+验收） |

## 五、需求分析师 Prompt 工程

### 5.1 需求分析模板

需求分析师在收到你的需求后，内部使用以下分析框架：

```
## 需求分析框架

### 1. 需求解读
- 核心功能是什么？
- 用户故事：作为 ___，我想 ___，以便 ___
- 交付物清单：哪些文件需要创建/修改

### 2. 技术决策
- 技术栈：{从工作区推断}
- 架构模式：{SPA / SSR / 组件库 / ...}
- 依赖要求：{是否需要新依赖}

### 3. 任务拆解原则
- 每个任务单一职责
- 任务粒度：15-30 分钟可完成
- 明确输入输出
- 标注阻塞依赖

### 4. 资源匹配原则
- 编码任务 → 编码助手 (Claude)
- 测试任务 → 测试专家 (Claude)
- 执行任务 → Shell 执行器 (bash)
- 审查任务 → 对应审查员

- 数据库任务 → 数据库设计师 (Gemini)
- 后端任务 → 后端开发 (Claude)

### 5. 编排原则
- 无依赖的任务并行执行
- 有依赖的任务串行排队
- 关键路径上的任务优先
- 审查和测试在编码后

| ✏️ 修改 | 回复具体修改意见 | 分析师调整计划后重新提交审批 |
| ❌ 驳回 | 回复 "驳回" / "重来" | 分析师重新分析需求 |
| ⏸️ 暂停 | 回复 "暂停" | 分析师暂停执行中的任务 |
| 🔄 追加 | 回复新的需求点 | 分析师在现有计划上追加任务 |

### 6.2 执行中的干预

执行过程中你可以随时干预：

```
// 暂停
你: "@需求分析师 暂停执行，我需要改一下需求"

// 追加
你: "@需求分析师 追加一个需求：用户列表要支持导出 Excel"

// 调整优先级
你: "@需求分析师 登录页优先，列表页可以延后"

// 更换策略
你: "@需求分析师 前端不用 Vue 了，改用 React"
```

## 七、golutra 中的实际操作

### 7.1 初始设置

```

   - sandboxed: false

### 7.2 首次使用

```
你 → 私聊 @需求分析师:
"你是需求分析师。从现在起，我会给你描述需求，请你：
 1. 分析并拆解为具体任务
 2. 推荐需要的 AI 员工组合
 3. 生成执行计划（含依赖和时间线）
 4. 等我审批通过后，统筹安排各员工执行
 5. 执行过程中定期汇报进度

我的项目技术栈：Vue 3 + TypeScript + Tailwind CSS + Pinia
后端：Node.js + Express + PostgreSQL

准备好了吗？"

需求分析师: "准备就绪。请描述你的第一个需求。"

你: "帮我做一个带搜索和分页的用户列表"

（分析师开始工作...）
```

### 7.3 统筹执行模式

审批通过后，需求分析师通过群聊 @提及 对应员工来分配任务：

```
需求分析师 → 群聊 @编码助手-1:
"请实现 UserList.vue 组件..."

需求分析师 → 群聊 @编码助手-2:

需求分析师 → 群聊 @编码助手-1:
"请将搜索和分页集成到 UserList 组件..."

（等集成完成后）

需求分析师 → 群聊 @测试专家:
"请为以上组件编写单元测试..."

需求分析师 → 你:
"📊 所有任务已完成。请验收。"
```

## 十、扩缩容建议

| 需求规模 | 推荐配置 | 员工总数 |
|---------|---------|---------|
| 小需求（组件/功能） | 1 分析师 + 1-2 编码 + 1 Shell | 3-4 |
| 中需求（模块） | 1 分析师 + 3 编码 + 1 测试 + 1 Shell | 6 |
| 大需求（系统） | 1 分析师 + 5 编码 + 2 测试 + 1 审查 + 1 Shell + 1 文档 | 11 |
| 全栈需求 | 方案五的配置 + 1 分析师 | 8 |

## 十一、注意事项

1. **需求描述越清晰，分析越准确**：虽然一句话就够，但关键约束（技术栈、设计要求）说清楚效果更好
2. **先审批再执行**：不要跳过审批步骤，确认计划合理再开始
3. **及时反馈**：执行过程中发现问题立即告知分析师
4. **不要同时给分析师多个需求**：一个需求完成后再提下一个
5. **分析师不写代码**：它只负责分析和调度，实际编码由其他员工完成
