## 三、职责定义

### 3.1 核心审查项

| 审查维度 | 检查项 | 严重级别 |
|---------|--------|---------|
| XSS | v-html、innerHTML、document.write | 🔴 严重 |
| CSRF | API token 传递、SameSite cookie | 🔴 严重 |
| 注入 | eval、new Function、template 注入 | 🔴 严重 |
| 认证 | JWT 处理、token 存储位置 | 🔴 严重 |
| 授权 | 前端路由守卫、API 权限检查 | 🟡 高 |
| 信息泄露 | console.log、硬编码密钥 | 🟡 高 |
| 依赖安全 | npm 包已知漏洞 | 🟡 高 |
| CSP | 内联脚本/样式兼容性 | 🟢 中 |
| 原型污染 | Object.assign、展开运算符 | 🟢 中 |

## 五、Prompt 模板库

### 5.1 全面安全审查

```
请从前端安全角度审查以下代码：

文件列表：
{文件路径}

检查项：
1. XSS 风险：v-html、innerHTML、document.write、eval
2. CSRF 防护：API 调用是否携带 token
3. 敏感信息：hardcoded credentials、localStorage 中的敏感数据
4. 依赖风险：已知漏洞的 npm 包
5. CSP 兼容：内联脚本/样式
6. 原型链污染：Object.assign 的安全性
7. 认证逻辑：JWT 处理、token 刷新
8. 输入验证：用户输入是否经过 sanitize

输出格式：
🔴 严重（必须修复，附修复代码）
🟡 高危（建议修复，附方案）
🟢 建议（最佳实践建议）
```

### 5.2 XSS 专项审查

```
专项检查 XSS 漏洞：

扫描所有 .vue 和 .ts 文件中的：
1. v-html 使用（是否经过 DOMPurify 处理）
2. innerHTML 赋值
3. document.write / document.writeln
4. eval / new Function / setTimeout(string)
5. 用户输入直接拼接到 DOM
6. URL 参数注入（location.href / search）

每个发现请给出：
- 文件:行号
- 风险描述
- 攻击向量示例
- 修复代码
```

### 5.3 依赖安全审计

```
审计项目依赖安全性：

1. 运行 npm audit 分析结果
2. 检查 package.json 中高风险包
3. 检查 lock 文件中的间接依赖
4. 评估每个漏洞的实际影响
5. 给出升级/替换建议
```

## 六、协作关系

```
上游：
  编码助手 → 代码完成 → 安全审查员

下游：
  安全审查员 → 审查报告 → 你（监工决策）
  安全审查员 → 修复建议 → 编码助手（修复）

平行：
  安全审查员 ←→ 架构审查员（不同维度，可能有交集）
```
